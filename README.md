# Go Practice

Go Practiceは、KataGoとの対局と棋譜の検討を1つの画面で行うローカルアプリです。初心者向けに強さを調整したAIと対局できます。対局中は、任意の局面へ戻ってKataGoの評価を確認したり、別の手順を試したりできます。

対局と検討に使う主な機能は次のとおりです：

- 5、6、7、9、13、19路盤でのAI対局
- 目差・勝率の推移、候補手、読み筋、ownershipの表示
- 棋譜の分岐を残したまま行う局面移動と変化の作成
- 局面ごとのメモと "重要な局面"
- SGF・JSONによる棋譜の読み込みと保存
- MCPに対応するAI agentとの局面検討

## 必要な環境

動作には次の環境が必要です：

- macOS
- Go 1.27.4
- Node.js 26.13.1
- pnpm 12.23.0
- KataGo 1.18.2と解析用のモデル・設定

Homebrewの`/opt/homebrew/opt/katago`または`/usr/local/opt/katago`にKataGoがある場合は、自動で検出します。モデルはHomebrewで配布される3つの固定ファイル名、解析設定は`analysis_example.cfg`を探します。それ以外のファイルを使う場合は、起動時に`--katago`、`--model`、`--config`を指定します。

アプリを初めてビルドする前には、フロントエンドの依存関係をインストールします。

```console
$ make setup
```

## 起動

Goの実行ファイルとフロントエンドをビルドしてから、アプリを起動します。`make build`は両方をビルドし、`make run`はビルド済みのアプリを起動します。`make run`はビルドを自動では行いません。

```console
$ make build
$ make run
```

起動後、ブラウザで`http://127.0.0.1:8080`を開きます。待受アドレスは`ADDRESS`、対局の保存先は`DATA_DIR`で変更できます。例えば、次のコマンドは待受ポートを18080へ変更し、棋譜を`/tmp/go-practice-games`へ保存します。

```console
$ make run ADDRESS=127.0.0.1:18080 DATA_DIR=/tmp/go-practice-games
```

KataGoを自動検出できない場合は、`SERVER_ARGS`を使ってパスを渡します。`--katago`には実行ファイル、`--model`にはモデル、`--config`には解析設定を指定します。指定した値は、`make run`からGo Practiceの起動引数へ渡されます。

```console
$ make run SERVER_ARGS='--katago /path/to/katago --model /path/to/model.bin.gz --config /path/to/analysis.cfg'
```

対局は着手、局面移動、メモの更新など、状態を変える操作ごとに`data/games`へ保存されます。局面の解析結果も同じ保存データに記録します。`DATA_DIR`を指定した場合は、その保存先を使用します。ブラウザやサーバーを再起動した後も、画面左側の「保存した対局」から再開できます。

## 対局

「新しい対局」から、盤サイズ、あなたの石の色、AIレベル、置き碁、コミを選びます。置石は5路盤で5子、6路盤で4子、7路盤・9路盤・13路盤・19路盤で9子まで選べます。中国ルールを採用し、置き碁による白への点数補正は行いません。互先のコミは7.5目、置き碁のコミは0.5目が既定値です。

AIレベルは段級位ではなく、KataGoの探索量と候補手の選び方を変える設定です。低いレベルではKataGoの第1候補以外も選びますが、石を取る手、アタリから逃げる手、直前の応酬など、局面に直接関係する手を考慮します。

対局の情報の欄（「対局」「分析」の切り替えの下）を押すと、あなたの石の色とAIレベルをいつでも変えられます。盤サイズ、置き碁、コミは変えられません。あなたの石の色を変えると、それまでの手のうち、どれがあなたの手かも変わります。SGFから読み込んだ対局は、あなたの石の色とAIレベルが未設定で始まります。未設定のまま対局モードに切り替えようとすると、先に設定の画面が開きます。

あなたが着手すると、その手を保存してからAIが応手を考えます。探索を止めたい場合は「中止」を押します。中止してもあなたの着手は残り、「AIの思考を再開」から同じ局面の探索を再開できます。

「待った」は、対局モードで使えます。開始局面から "現在の局面" までの手順のうち、最も新しいあなたの操作（着手、パス、投了）と、その後のすべての局面を取り消します。AIの思考を中止した直後は、応手を待たずにあなたの着手を戻せます。戻した手順は削除されず、「棋譜・変化」に変化として残ります。

## 局面の分析

盤面の右側には、 "現在の局面" に対するKataGoの解析結果が表示されます。局面全体の評価欄と推移グラフは、黒から見た目差と勝率を示します。候補手ごとの勝率と目差は、その局面の手番側から見た値です。visitsと読み筋も候補手ごとに確認できます。盤上の「候補手」は候補の位置を示し、ownershipは各交点が黒・白のどちらに支配されそうかを色で示します。

「棋譜・変化」または評価グラフで局面を選ぶと、その局面へ移動し、表示が分析モードへ切り替わります。分析モードではAIの応手を待たずに盤面へ着手できるため、 "現在の局面" から別の手順を試せます。候補手の行をダブルクリックすると、その候補手から変化を作れます。

棋譜ツリーの局面を右クリックすると、右クリックした局面以降を削除できます。開始局面は削除できません。主分岐の局面を削除した場合は、同じ親局面に残る最初の変化を主分岐へ繰り上げます。変化の局面では、その手順を主分岐にする操作も選べます。主分岐にした手順は、棋譜を進めるときに優先してたどります。対局モードで着手、パス、AIの手、投了、待ったを行うと、 "現在の局面" を通る手順が主分岐になります。

キーボードでは、現在の変化を`PageUp`で主分岐にできます。 "現在の局面" 以降は、`⌘ + Delete`または`⌘ + Backspace`で削除できます。`?`を押すと、局面移動や表示切り替えを含むショートカットの一覧が開きます。「メモ・重要な局面」では、局面ごとにメモを残し、後で見返したい局面を "重要な局面" にできます。

## 棋譜の読み込みと保存

### 画面での操作

画面上部の「インポート」から「SGFを読み込む」または「JSONを読み込む」を選びます。読み込むファイルの文字コードにはUTF-8を使います。書き出すときは「エクスポート」を開き、「SGFで保存」または「JSONで保存」を選びます。「保存した対局」の右にある操作から、保存した各対局の名前の変更と削除も行えます。

起動時に読み込めない保存ファイルがあっても、そのほかの対局は読み込みます。読み込めなかったファイル名と理由は画面に表示し、MCPの`list_storage_errors`からも取得できます。不正なファイルを自動で書き換えることはありません。

### SGFの対応範囲

SGFはFF[4]に対応し、1つの正方形の囲碁棋譜だけを読み込みます。`FF`を省略すると規格上はFF[1]になるため、`FF[4]`を明示した棋譜を読み込みます。盤サイズは5、6、7、9、13、19路盤、文字コードはUTF-8、中国式の面積計算に対応します。非ASCII文字を含む棋譜では`CA[UTF-8]`も明示する必要があります。

`RU`と`KM`を省略した棋譜も読み込めます。省略した値は書き出しでも追加せず、内部では中国式の面積計算と、互先7.5目・置き碁0.5目の既定値を使います。コミは-100目以上100目以下の0.5目単位で指定します。初期配置の石を取り除く`AE`には対応しません。読み込んだ`AP`は置き換えません。

主分岐、変化、初期配置、対局者、結果、コメント、未知のプロパティを保持します。目数（持碁を含む）と投了は意味を対局へ反映し、それ以外の結果は値をそのまま記録します。

対局日`DT`は、前後のSGFの空白を除いて日付として検査し、複数の日付がある場合は先頭を使います。読み込んだ値は空白を含めて保持し、書き出しでも同じ値を使います。先頭の日付がISO 8601の`YYYY-MM-DD`、`YYYY-MM`、`YYYY`のいずれかであれば、対局一覧の開始日に使います。対応していない値は、読み込みを中止して理由を表示します。`DT`がない棋譜は、開始日時を不明とし、書き出しでも`DT`を書きません。

開始日時が不明の対局は、対局一覧では読み込んだ時刻の位置に並びます。対局名`GN`もない場合は、読み込んだ時刻から`YYMMDD-HHMM読込`という対局名を付けます。

SGFにはAIレベルとあなたの石の色がないため、読み込んだ対局ではどちらも未設定になります。JSONを読み込む場合は、開始日時と`DT`、対局名と`GN`がそれぞれ一致することも確認します。

### 文章とプロパティの正規化

対局名にはSGFの`GN`を使い、画面で名前を変更した場合も同じプロパティの位置へ反映します。空の`GN`は対局名として保持せず、値の前後にあるSGFの空白も取り除きます。SGFの文章型ではCRLF、LFCR、CRをLFへそろえ、単行文章型では改行を空白へ変えます。タブ、垂直タブ、改ページは半角空白へ変えます。全角空白とNBSPはSGFの空白ではないため、そのまま保持します。JSONから読み込む対局名、変化名、SGFプロパティにも同じ正規化を適用します。未知のプロパティでも、SGFの規則に従って改行、ソフト改行、エスケープを解釈します。そのため、読み込んだ文字列の改行コードやエスケープ表現は、同じ意味の正規形で書き出されます。

SGFは、意味を変えない範囲で正規形へ書き出します。例えば、`KM[+6.5]`は`KM[6.5]`、圧縮した点の範囲は個別の点、盤サイズに応じた旧式のパス表現は空の着手として書き出します。省略時の既定値を内部で使う`SZ`、明示された開始手番や置き碁の情報は、読み込んだ指定の有無を保ちます。

### 結果の扱い

二連続パスで終わる手順に目数の結果がある場合は、`TB`と`TW`があれば、その範囲にある相手の石を死石として扱います。地の範囲がなければ、KataGoのownershipを使って死石を決めます。死石を取り除いて数えた結果と`RE`が一致する場合だけ、棋譜を読み込みます。

目数（持碁を含む）と投了は、勝者や目差などの意味を対局へ反映します。それ以外の結果は、`RE`の値を解釈せずに記録して、対局を終局として扱います。例えば、`RE[W+T]`、`RE[W+F]`、`RE[W+]`、`RE[Void]`、`RE[?]`は、画面ではいずれも「終局」と表示し、SGFへ元の値をそのまま書き出します。

主分岐の末端では主分岐の結果を表示し、それ以外では "現在の局面" に記録された結果を表示します。終局後に着手が続く棋譜は、終局した手順と続行した手順を変化として区別し、再度書き出しても両方を保持します。

点数の内訳では、黒と白について盤上の石と地を数え、白の点数にコミを加えます。負のコミでは、両方の点数にコミの絶対値を加え、どちらの点数も負にならないようにします。

### 未知のSGFプロパティ

Go Practiceが意味を扱わないSGFプロパティは、識別子が`GP`で始まる場合も含め、ほかの未知のプロパティと同じように保持します。書き出しでは、読み込んだ局面と値を保ったまま出力します。文章型の空白やエスケープなど、SGFの規則で正規化される表現は、同じ意味の正規形になります。

Go Practiceが新しく記録する情報には、SGF FF[4]の標準プロパティだけを使います。 "重要な局面" は`HO`、死石を取り除いて数えた地の範囲は`TB`と`TW`、開始日は`DT`へ記録します。AIレベル、あなたの石の色、正確な開始時刻など、標準プロパティで表せない情報を含める場合はJSONを使用します。

### 入力と保存の上限

メモは4000文字以下、対局名と変化名は80文字以下を受け付け、上限を超えた入力は保存や読み込みを拒否します。読み込むSGFとJSON、および書き出すSGFとJSONは10MiB以下です。棋譜には開始局面を含めて4096局面まで記録でき、変化の入れ子も4096段まで受け付けます。操作後のSGFまたはJSONが上限を超える場合は、その操作を保存せずに拒否します。AIレベルやあなたの石の色など、SGFに書き出さない情報も含めて保存する場合は、JSONを使用します。

## AI agentとの局面検討

Go PracticeはMCPの標準入出力サーバーを備えています。MCPに対応するAI agentへ登録すると、 "表示中の局面" を共有し、その局面について質問できます。AI agentは局面の解析と棋譜編集に加え、対局の作成・操作・読み書き・管理を行えます。

MCPサーバーは、次の機能をツールとして公開します：

- 局面検討：`get_selected_position`、`select_position`、`analyze_position`、`show_variation`、`get_analysis`
- 対局管理：`list_games`、`reorder_games`、`list_storage_errors`、`get_game`、`create_game`、`rename_game`、`update_game_settings`、`delete_game`
- 対局操作：`play_move`、`request_ai_move`、`resign_game`、`undo_move`
- 棋譜編集：`navigate_game`、`update_node`、`play_variation`、`delete_variation`、`promote_variation`
- 読み書き：`import_sgf`、`import_json`、`export_sgf`、`export_json`

次の例では、`/path/to/go-practice`をこのリポジトリの絶対パスへ置き換えます。MCPサーバーの登録形式はクライアントごとに異なります。設定する場所や手順は、利用するクライアントの説明に従ってください。

```json
{
  "command": "/path/to/go-practice/bin/go-practice",
  "args": ["mcp", "--server-url", "http://127.0.0.1:8080"]
}
```

AI agentを利用する間は、Go Practiceを`http://127.0.0.1:8080`で起動しておきます。MCPサーバーを登録した後は、AI agentとの新しい対話を開きます。その対話では、Go Practiceが公開するツールを利用できます。

## 開発

ここからは、Go Practiceの実装を変更するときに使う手順です。用途に応じて、ビルド、開発用サーバー、ログ、検査の各コマンドを使い分けます。各コマンドはリポジトリのルートで実行します。利用できるすべてのコマンドと説明は、`make help`で確認できます。

### ビルド

Goの実行ファイルと本番用フロントエンドは、まとめてビルドすることも、変更した対象だけをビルドすることもできます。`make build.server`は`bin/go-practice`を作成し、`make build.web`はフロントエンドのビルド成果物を`web/dist`へ出力します。`make clean`を実行すると、この2つのビルド成果物を削除します。

```console
$ make build
$ make build.server
$ make build.web
```

### 開発用サーバー

フロントエンドの変更を確認するときは、GoのAPIサーバーとViteの開発サーバーを別々に起動します。Goの実装を変更した場合は、先に`make build.server`を実行してください。最初のターミナルでは、次のコマンドでAPIサーバーを起動します。

```console
$ make run.server
```

別のターミナルでは、次のコマンドでViteを起動します。起動後、ブラウザで`http://127.0.0.1:5173`を開きます。開発用サーバーはAPI要求を`http://127.0.0.1:8080`へ転送するため、APIサーバーも既定の待受アドレスで起動します。

```console
$ make run.web
```

### ログ

HTTP要求、対局の保存、AIの応手、KataGo解析、解析キャッシュの詳細を確認する場合は、APIサーバーのデバッグログを有効にします。環境変数`LOG_LEVEL`を指定すると、起動方法を変えずにログレベルを切り替えられます。本番用フロントエンドと一緒に起動する`make run`でも、同じ環境変数を使用できます。

```console
$ LOG_LEVEL=debug make run.server
```

ログレベルには`debug`、`info`、`warn`、`error`を指定できます。既定値は`info`です。`--log-level`を指定した場合は、環境変数`LOG_LEVEL`よりコマンドラインの値を優先します。MCPサーバーにも`--log-level`を指定でき、環境変数`LOG_LEVEL`を既定値として使います。

### 起動オプション

KataGoへ追加の設定を渡す場合は`--override-config`、フロントエンドの成果物を変更する場合は`--web-dir`を使います。

### テストと静的検査

`make check`は、データ競合検査付きのGoテスト、Goの整形検査、`go vet`、deadcode、staticcheck、フロントエンドの自動テスト、Biomeによる静的検査・整形検査、型検査をまとめて実行します。本番用ビルドは行わないため、`web/dist`は変更されません。

```console
$ make check
```

Goとフロントエンドのテストだけを実行する場合は、`make test`を使います。このコマンドも、Goテストにデータ競合検査を含めます。Goだけのテストは`make test.server`で実行でき、Goの整形検査と静的検査だけを実行する場合は、`make check.server`を使います。フロントエンドでは、静的検査と整形検査をまとめて確認する`make check.web`のほか、`make test.web`、`make lint.web`、`make typecheck.web`を個別に実行できます。フロントエンドを自動整形する場合は、`make format.web`を実行します。

CIでは、Goの整形検査、`go vet`、deadcode、staticcheck、データ競合検査付きテストに加え、フロントエンドの自動テスト、静的検査・整形検査、型検査、本番用ビルドを実行します。
