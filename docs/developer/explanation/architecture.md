# ブラウザ・MCP・Goサーバーの関係

## 対局画面とHTTP API

ブラウザの対局画面は、着手や局面移動をHTTP APIへ送る。例えば、ブラウザで着手すると、Goサーバーが対局に着手を適用し、状態を保存する。Goサーバーは、対局と棋譜の分岐、解析結果を管理し、AIの応手や局面の評価が必要なときにKataGoを呼び出す。

本番用のフロントエンドはGoサーバーが配信する。開発時はViteが画面を配信し、`/api`への要求を既定のGoサーバーである`http://127.0.0.1:8080`へ転送する。このため、開発用の画面もGoの状態管理と棋譜の保存を利用する。

## MCPクライアントとHTTP API

AI agentのクライアントは`go-practice mcp`と標準入出力で通信する。MCPサーバーはツール呼び出しを起動済みのGoサーバーへのHTTP要求に変換する。例えば、`get_selected_position`は`GET /api/agent/context`を呼び、利用者が画面で選んだ局面を取得する。後続の解析や変化表示で同じ`contextId`を渡せば、取得した局面を基準に要求を送れる。
